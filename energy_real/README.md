# Reproducible energy-memory and reasoning experiments

This package contains the repaired byte-LM implementation, full-state trainer,
fixed-backend kernels, small memory studies, and a separate local-model adapter.
It is an experimental implementation, not a competitive general-purpose model.

## Mixed energy and local attention

`LM(Config(kind='hybrid', attention_window=64))` uses local attention in every
third layer and energy recurrence in the other layers. The attention cache
retains at most 64 tokens, along with segment and absolute-position metadata.
The default `kind='energy'` and `kind='softmax', attention_window=0` behavior is
unchanged. A positive attention window on a softmax model creates the windowed
Transformer control.

```bash
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 .venv/bin/python -m energy_real.competitive_study \
  --out runs/my_comparison --steps 1000 --seeds 11 22 33 --max-seconds 5400

# Standalone mixed training uses the ordinary resumable trainer:
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 .venv/bin/python -m energy_real.train \
  --kind hybrid --attention-window 64 --attention-every 3 \
  --width 64 --layers 3 --heads 2 --slots 8 --ff-width 192 \
  --device cpu --amp none --seq 128 --batch 8 --steps 1000 \
  --out runs/my_mixed_model
```

The controlled comparison matches parameter counts and training bytes and reports
unequal compute costs explicitly. See [architecture](../reports/competitive/ARCHITECTURE.md)
and [executed results](../reports/competitive/REPORT.md). A mixed checkpoint has a
different layer layout from the earlier energy-only checkpoint; use the recorded
configuration when loading it. Optional fact readers can be enabled on either.

### Equal-compute confirmation and faster execution

The [new confirmation](../reports/compute_confirmation/REPORT.md) uses compiled
training, foreach AdamW, equal learning-rate search budgets, and fixed CPU-time
blocks on one core. The hybrid reaches 2.512 test bits per byte versus 2.578 for
full attention and 2.577 for windowed attention at 128 bytes, across three seeds.
The comparison matches steady-state update time; compiler setup, validation
and I/O costs are separate. It remains a small, single-corpus CPU experiment.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
TORCHINDUCTOR_COMPILE_THREADS=1 .venv/bin/python -m energy_real.compute_study \
  --out runs/my_compute_confirmation --cpu 19 --quantum .5 --compile --foreach \
  --seeds 404 505 606 --pilot-seed 47 --validation-seed 92101 --test-seed 92102 \
  --pilot-seconds 20 --fit-seconds 90 --max-seconds 3600
```

CPU 19 is the performance core selected on this host; choose an allowed core
on another machine. The run freezes all validation selections before test and
records scheduling progress, compiler warmup, training bytes and wall time.
It uses the existing cumulative research-budget ledger and refuses an existing
output directory. Frozen source archives reproduce the historical protocols.

The kernel uses an explicit CPU slot reduction and a direct one-token update.
For an already loaded full-attention model,
`energy_real.static_cache.with_static_cache(model, capacity=32784)` returns an
evaluation copy with preallocated KV storage. Use it with gradients disabled,
pass only its latest returned state, and pass `None` to start a new stream.
The fixed capacity is counted in memory measurements; weights keep their
ordinary checkpoint format. See [timings and limits](../reports/stronger_comparison/REPORT.md).

### Sampling native checkpoints

The sampler is part of the installable package and works outside the checkout:

```bash
python -m energy_real.sample --checkpoint /path/to/selected_hybrid.pt \
  --prompt 'The ' --tokens 128

python -m energy_real.sample --checkpoint /path/to/selected_hybrid.pt \
  --prompt 'The ' --tokens 128 --temperature 0.8 --top-k 40 --seed 42 \
  --prefill-chunk 256 --output sample.bin
```

`--tokens` counts new bytes. Zero temperature selects greedy decoding; positive
temperature enables seeded sampling, and `--top-k 0` considers all 256 byte
values. The default prompt chunk is 256 bytes, bounding each model call's
activations and logits. Full-attention checkpoints still retain their growing
KV cache. The Python API is `energy_real.sample.sample_bytes(model, prompt_bytes,
...)`; it returns the complete prompt plus generated bytes and leaves global RNG
state and model weights unchanged.

The console decodes UTF-8 with replacement for invalid sequences. `--output`
preserves the exact bytes and refuses an existing destination. The earlier
`python -m scripts.sample_native` command remains an alias from the checkout.
Sampling runs without external facts; use `HybridSession` for fact-reader use.
The small trained model remains a byte predictor with repetitive generation.

## Native hybrid architecture

`LM(Config(memory_dim=32))` adds a zero-gated reader in every native block.
`HybridSession` connects those readers to the existing `FactStore`, resets
recurrent state on committed revisions, and executes bounded graph programs.
The existing native checkpoint's weights remain compatible through explicit
augmentation. See [architecture](../reports/hybrid_integration/ARCHITECTURE.md)
and [measured integration results](../reports/hybrid_integration/REPORT.md).

```bash
# Create a separate weight-only checkpoint with initially closed fact readers:
.venv/bin/python -m energy_real.hybrid augment \
  --checkpoint runs/enwik8_energy_10m/best.pt --out runs/my_hybrid_initial.pt

# Evaluate a supplied program against an existing reviewed fact store:
.venv/bin/python -m energy_real.hybrid query \
  --store runs/my_facts.sqlite --program path_program.json

# Read the store while generating with a memory-enabled checkpoint:
.venv/bin/python -m energy_real.hybrid generate \
  --checkpoint runs/hybrid_native/selected.pt --store runs/my_facts.sqlite \
  --prompt 'ar?' --tokens 16

# Optional local learning in the native trainer (BP remains the default):
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 .venv/bin/python -m energy_real.train \
  --out runs/native_pcalm_new --device cpu --amp none --learning-rule pcalm \
  --activity-steps 8 --state-lr .02 --dual-lr .1 --rho 1 \
  --width 32 --layers 4 --heads 2 --slots 8 --ff-width 64 \
  --seq 16 --batch 2 --steps 32 --eval-every 16 --eval-bytes 512 --max-seconds 300
```

A program file contains typed operations and references to previous results:

```json
{"steps":[{"operation":"entity","arguments":["parcel"]},{"operation":"follow","arguments":["0","owned_by"]},{"operation":"follow","arguments":["1","works_at"]}]}
```

In Python, use `GraphProgram.path(subject, relations)` and
`HybridSession.load(checkpoint, store).answer(program)`. Authorized writes still
use `FactStore.apply(..., authorized=True)` with a matching revision and request
ID. Model proposals do not authorize themselves. Exact graph answers and neural
generated text remain distinct outputs; generated text is not automatically
supported by the returned facts.

The reader-adaptation runner freezes original weights and tests memory enabled,
disabled, and shuffled after validation freezes all selected checkpoints:

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 .venv/bin/python -m energy_real.hybrid_study \
  --checkpoint runs/enwik8_energy_10m/best.pt --out runs/hybrid_readers_new \
  --steps 500 --max-seconds 2400
```

This experiment supplies a small symbol vocabulary, query grammar, and event
semantics. It validates integration, not general language reasoning. Plain byte
training has no fact snapshots, so merely passing `--memory-dim 32` to the native
trainer does not teach a useful fact reader. Applications must supply aligned
facts through `LM.forward(..., memory=...)` during relevant supervised training.
The selected artifact was trained on three/four-fact snapshots and failed the
single-fact neural transfer check. Its exact graph-program answers still worked;
use that interface for factual answers outside the reader's narrow training setup.

## Local learning and full energy predictors

`local_energy.py` adds independent residual predictors trained by BP, predictive
coding, or PC-ALM. PC-ALM uses local activity descent and dual ascent with no
backpropagation through the activity history. A separate conditional EBM scores
every candidate answer by minimizing its scalar energy. It includes a small
256-way next-byte model. Neither architecture removes continuous hidden states.

`discrete_energy.py` provides the alternative with explicit entity/path states:
seven learned scalar factor costs and exact sum-product inference, with supplied
event semantics and feature predicates. There are no learned embeddings in this
model. A fixed min-sum graph control is also included.

The bounded study compares three seeds, freezes checkpoint/temperature choices
on validation, preserves initialization controls, and charges a cumulative
eight-hour ledger. The [design and limitations](../reports/local_energy/DESIGN.md)
explain the distinctions and assess graph, program, memory, and topology ideas.

```bash
# Download Fashion-MNIST and verify the published checksums once:
.venv/bin/python -c 'from pathlib import Path; from energy_real.local_energy_data import download_fashion; download_fashion(Path("data/fashion_mnist"))'

# Requires the existing data/enwik8 for the byte task; --tasks graph is offline.
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 .venv/bin/python -m energy_real.local_energy_study \
  --out runs/local_energy_new --max-seconds 7200

CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 .venv/bin/python -m energy_real.discrete_energy \
  --out runs/discrete_energy_new --max-seconds 300

# Inspect features with frozen models; this does not update the models:
.venv/bin/python -m energy_real.local_energy_analysis probes \
  --study runs/local_energy_new --out runs/local_energy_new/feature_probes.json

# Greedy generation with the selected seed-11 full energy byte model:
.venv/bin/python -m energy_real.local_energy_analysis generate \
  --study runs/local_energy_new --fit bytes_energy_d3_w32_mem0_seed11 \
  --prompt 'The world ' --tokens 32 --out runs/local_energy_new/generation.json

# Reproduce the longer byte-study configuration on its preserved fresh segment:
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 .venv/bin/python -m energy_real.local_energy_study \
  --out runs/local_energy_byte_new --tasks bytes \
  --byte-data runs/local_energy_byte_corpus/enwik8_300000_600000 \
  --byte-steps 2000 --byte-valid 512 --byte-test 1000 --max-seconds 1200
```

Use a fresh output directory for each experiment. The neural study supports
`--resume` with unchanged source, configuration, data, and committed optimizer
state. A crashed unclosed budget reservation is charged conservatively; ordinary
handled interruptions charge actual elapsed time. Historical reports stay unchanged.

The [completed report](../reports/local_energy/REPORT.md) links the trained model
archive, frozen selections, full results, and verification evidence. The longer
byte configuration uses a different corpus segment from the short experiment;
their absolute scores are not a paired learning curve. Both are tiny next-byte
predictors, and their generated text is not coherent language.

Graph memory uses a fixed causal quadratic writer and separately learned readers
per block. Every neural arm receives the same current facts. The graph tasks
test withheld relation compositions, longer paths, updates, missing values, and
explicit HOLD delays. They do not test language parsing or learned temporal
credit assignment. The next-byte run is a tiny context-limited prototype.

## Kernels and caches

`Config.kind` accepts `energy` and `softmax`. There is no language-model `delta`
alias. `Config.backend` accepts `dmat` (default) or `matmul`.

Both kernels factor the existing energy recurrence into a precision scan and
chunkwise state contraction. `dmat` forms causal within-chunk decay matrices and
supports strong forgetting. `matmul` is an explicitly selected optimization with
a checked log-span limit; crossing it stops the run. Data-dependent algorithm
switching was removed because it changed earlier rounding when future inputs
changed. The old throughput numbers must be remeasured for the chosen backend.

Energy state remains `(precision, information)` per layer. Softmax state is
`(keys, values, segment_ids)` so resets cannot read previous segments. An old
`(keys, values)` state is interpreted as a single segment. State is not mutated.

## Training and exact resume

The preserved local enwik8 file uses a 90M/5M/5M split. Its complete SHA-256 is
checked before training, and source/configuration/runtime identities are saved.
An alternative corpus fingerprint must be supplied explicitly with
`--data-sha256`; size checks still apply.

```bash
.venv/bin/python -m energy_real.train --kind energy --out runs/new_energy \
  --backend dmat --steps 1000 --max-seconds 1800 --max-tokens 8192000

# Same schedule, data, source, and runtime; restores optimizer and RNG as well:
.venv/bin/python -m energy_real.train --kind energy --out runs/new_energy \
  --backend dmat --steps 1000 --max-seconds 1800 --max-tokens 8192000 --resume

# A new optimizer trajectory, explicitly labelled as a warm start:
.venv/bin/python -m energy_real.train --kind energy --out runs/warm_energy \
  --warm-start runs/enwik8_energy_10m/best.pt --steps 1000 --max-seconds 1800
```

`last.pt` commits weights, optimizer, Torch/CUDA/NumPy RNG state, actual step and
token counts, best-checkpoint state, identities, elapsed time, and an exact log
prefix. Extra crash-tail bytes are preserved separately. Corrupt committed logs
or incompatible resume identities are rejected. `best.pt` is for evaluation;
historical weight-only files cannot recover the interrupted optimizer state.

CUDA commands refuse to start over an unrelated GPU workload. Allocation and
time limits are explicit. The trainer does not increase budgets on resume.

## Memory mechanism study

```bash
OMP_NUM_THREADS=2 .venv/bin/python -m energy_real.memory_eval \
  --out runs/memory_baselines.json --per-family 10

OMP_NUM_THREADS=2 .venv/bin/python -m energy_real.memory_research \
  --out runs/controller_study --steps 60 --seeds 11 22 33 --max-seconds 900
```

This reuses `EditMemory` from the existing geometric-memory research. Operations
and addresses are supplied. The predictive objective concerns the next symbolic
value token **before** a write; it is not full-text language-model training.
The augmented objective adds delayed-query and edit-locality losses. Validation
selects weights before held-out testing, including the option of step zero.

Exact, diagonal, precision-aware, delta, preconditioned-delta and projected
controls cover updates, deletion, unknown facts, near addresses, overload,
distractors and multi-hop retrieval. The projected and preconditioned mechanisms
are treated as algebraic equivalence controls. Registry/provenance costs are
reported separately from raw state and cannot justify a misleading memory win.

## Separate practical adapter

```bash
.venv/bin/python -m energy_real.reasoning demo --out runs/memory_demo

# Uses the existing service; does not launch or modify LoopTest/llm-stack:
.venv/bin/python -m energy_real.reasoning evaluate --out runs/reasoning.json \
  --base-url http://127.0.0.1:8100 --score

# Separate diagnostic: predicted edits in disposable evaluation stores:
.venv/bin/python -m energy_real.reasoning evaluate --out runs/text_edits.json \
  --input-mode model_proposals --score
```

`FactStore.propose(text)` returns proposed edits and source references; it does
not write. `apply(reviewed_edits, expected_revision=..., request_id=...,
authorized=True)` is the caller's explicit reviewed action. `query(Query(...))`
returns evidence and either an answer or abstention. String queries have a narrow
local grammar (`Follow relation/relation from subject.`); broader interpretation
uses the configured service. This store is separate from the legacy protected
16-name/16-location ledger.

Approximate retrieval may return wrong or stale evidence. Those errors remain
visible in comparisons. Generation and multiple-choice scoring are separate.
The adapter records service identity, exact decoding settings, controller hash,
per-response model identity and supplied evidence. Arm order rotates across
episodes. Completed generation is saved before scoring, so a scoring outage
preserves the answer with scoring marked pending. Summaries count scored
episodes separately and retain generation accuracy, support accuracy, abstention
and latency even in partial runs. When
the service omits token usage, context tokens are `null`; bytes are reported
without calling them tokens. Unavailable service results are marked pending.


The persistent ceilings are 30 minutes for smoke checks, 90 minutes for checkpoint
evaluation/profiling, four hours for controllers, and two hours for reasoning:
eight GPU-hours maximum. The small controller study can run entirely on CPU.
Pending stages may be retried with the same ledger and unchanged source.
Failed, interrupted, incomplete or exhausted stages are not automatically rerun
or given extra time. SIGINT/SIGTERM stops the runner’s own child process group,
waits for cleanup, and persists elapsed time and interruption status. A successful
exit requires a valid completed report; missing, malformed or pre-existing output
cannot certify success. A source change requires a new stage directory; account
for time already used in earlier ledgers before assigning any remaining budget.
`--base-url` selects the service for both the reasoning health check and commands. No cloud spending, scale-up,
publication, or pretrained-model fine-tuning is performed by this runner.


## Shared recall and reasoning study (v2)

The audited v2.1 benchmark uses 384 training, 120 validation and 360 test episodes by
default. Entity namespaces and wording templates are disjoint. Each episode’s ID and
content remain stable when a caller requests a larger or smaller sample. Queries cover
one to three different relation types, corrections, missing intermediate links,
near-colliding addresses and capacity overload. Generated datasets and full
per-episode outputs remain under ignored `runs/` directories.

```bash
# Twelve seed-11 screens, then seeds 22/33 for each selected mechanism.
# CPU execution avoids occupying the GPU; the ledger still charges wall time.
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  .venv/bin/python -m energy_real.stages --out runs/reasoning_v2_final_stages \
  --prior-ledger runs/reasoning_v2_stages/stages.json --stages controllers
```

The controller sweep compares precision energy and preconditioned delta at
widths 16/32/64 and priors 0.01/0.001, with 500 optimizer updates per fit. Training
minimizes delayed recall cross-entropy plus 0.1 times unrelated-read locality
loss. Every episode also queries an unseen address; deleted addresses use an
explicit null target. Initialization is a separately calibrated control.

Confidence calibration uses validation only: score thresholds 0.05/0.15/0.3/0.5/0.7
and top-two margins 0/0.02/0.1/0.2. Validation is checked at initialization and every
100 updates. Selection favors accuracy, fewer unsupported answers, then support
accuracy; tied configurations prefer smaller width, then the larger prior. Exact
ties retain initialization or the earlier training step. Calibration ties prefer
stricter score/margin thresholds. Test data is instantiated only after the final
selection manifest and controller checksums are frozen.

Per-hop traces show the top candidates, score, confidence margin, selected fact
and abstention. Evaluation distinguishes incorrectly ranked facts from correct
candidates rejected by the confidence threshold. Selected weights are evaluated
against their initialization and against the original 16-dimensional configuration
on the same fresh test episodes. These are structured-memory results; language
reasoning results are separate.

Cost reports include database bytes, serialized active facts/history and registry,
model parameters and recurrent tensors. Isolated Linux subprocesses measure full
resident peaks from `/proc/self/status` (`VmHWM`), including Python/native/SQLite
overhead and excluding inherited pre-exec high-water marks. Disk and resident bytes
are reported separately. Timings include writes, state build and repeated queries
with balanced arm order. CPU measurements do not establish a GPU efficiency win.
